Metal / Mac Mini – shader rules (updated)

1. Alpha
    pAlpha does not exist on Metal.
    Transparency must always be handled in the fragment's output alpha (half4 or float4).

    Manual alpha blending is done directly on the colour vector:
        fragCol.rgb = fragCol.rgb*(1-a) + dropCol.rgb*a;
        fragCol.a   = fragCol.a + a*(1-fragCol.a);

2. lerp
    lerp(half3, half3, float) crashes on Mac/Metal.
    If you want to use lerp, all three arguments must have the same type and dimension:
        float3 result = lerp(float3(a), float3(b), float3(alpha,alpha,alpha));
    Simpler and more stable: do the blending by hand as above.

3. smoothstep / maths intrinsics
    smoothstep(edge0, edge1, x) only works if all arguments have the same type (float recommended).
    Half precision (half) can crash on Metal.
    Alternative: a manual smoothstep:
        float t = saturate((x - edge0)/(edge1 - edge0));
        float s = t*t*(3-2*t);

4. Rotation / tilt
    Tilting drops/snow: a 2D rotation of the coordinates, then multiply by a stretch if you like.
        float2 dvRot;
        dvRot.x = dv.x*cosA - dv.y*sinA;
        dvRot.y = dv.x*sinA + dv.y*cosA;

5. Colour and type
    Coordinates, position calculations: float
    Colour: half (saves memory)
    All blending and alpha must be done in the same type, no implicit conversion between half/float

6. Practical rules of thumb
    Avoid HLSL-like intrinsics with half on Apple GPUs (e.g. lerp, smoothstep) → do the calculations in float, convert to half on output.
    All "Shadertoy"-like variables (fragColor, pAlpha) must be mapped to the Metal standard: half4 or float4 output.
    Transparency must always be handled in the output alpha, not through a separate variable.
